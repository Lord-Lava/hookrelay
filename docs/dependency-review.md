# Dependency review — 2026-11-16

Testcontainers modules moved from 1.20.6 to Spring Boot 4.1.2's managed 2.0.5.
Core was already 2.0.5; no runtime application dependency version changed. The
2.x module coordinates are `testcontainers-junit-jupiter`, `testcontainers-postgresql`
and `testcontainers-rabbitmq`. Tests now use the public `org.testcontainers.postgresql`
and `org.testcontainers.rabbitmq` packages and the non-generic PostgreSQL container.
This removes the mixed-major compatibility dependency, without adding a second BOM.

Build-plugin classpath locking is now enabled in addition to application locking.
The Docker build copies all three lockfiles and verification metadata. It packages
with `bootJar`; integration tests run on a host/CI runner with Docker access before
image construction. No tests or verification checks were disabled in `check`.

Verification metadata was generated using an empty Gradle dependency cache, the
pinned Wrapper and only Maven Central/Gradle Plugin Portal. Parent POMs and Gradle
module metadata requested on fresh resolution are now covered. The original
Docker failure was missing verification entries, not the version assertion.

`scripts/verify-dependency-provenance.py` independently checks every recorded
SHA-256 against the official repository's published SHA-256, or independently
hashes an official artifact download when that checksum is not published. Plugin
marker POMs are checked against the Plugin Portal first, matching resolution order:
some publishers provide different marker POM bytes on Maven Central. Marker POMs
are downloaded and hashed directly: the Boot marker's Portal `.sha256` URL
returns Central's checksum even though its POM URL serves Portal-generated bytes.
The downloaded Portal POM matched the recorded SHA-256 and references the expected
`spring-boot-gradle-plugin:4.1.2` artifact. This is a
repository provenance check, not publisher signature authentication or an SCA scan.
It never edits or automatically accepts metadata. Review the generated report and
metadata diff before committing dependency updates.

The clean-cache build command was:

```sh
GRADLE_USER_HOME=/tmp/hookrelay-trusted-resolution ./gradlew spotlessApply clean check bootJar dependencies --write-locks --write-verification-metadata sha256
```

Result: passed, 149 tests, zero failures/errors/skips, Java 25, Gradle 9.9.1.
The lockfile diff changes only the five legacy Testcontainers modules to 2.0.5;
build-plugin locking adds the existing plugin classpath without version overrides.
